# CircuitFabric 桌面控制面界面设计

[English](desktop-ui-design.md)

> 本文件是桌面控制面（`apps/circuitfabric-desktop`，GPUI + `gpui-component`）的界面设计基线。它回答两个问题：**界面怎么分类**（信息架构）和**界面长什么样**（视觉与布局）。每个页面下带 `[TODO]` 标记的是"界面入口已规划、具体功能尚未实现"的部分——导航和布局先行，功能后置。

## 1. 设计定位与原则

桌面控制面是**工程控制台**，不是第二个原理图编辑器，也不是第二个对话客户端。它负责项目、授权文档、EDA 服务/bridge 健康、运行时端点与 API Key 引用、技能/MCP 授权、会话/任务/审计、用量、语义查询与 BOM 导出；原理图编辑与 EDA 内对话属于各 backend/bridge 插件。

设计原则（贯穿全站）：

1. **按工作流分类，不按技术分层分类**。用户沿着"建项目 → 授权文档 → 连 EDA → 配智能体 → 跑会话 → 审变更 → 导出"的流程找入口，而不是沿着"存储/融合/物化"的层找。
2. **状态可读、绝不伪装**。写入成功、回读成功、验证成功是三种独立状态；`inconclusive`（未能回读）永远用琥珀色表示"未知"，绝不显示成绿色"成功"。
3. **安全优先**。高危物化必须显式审批并绑定基线快照 + 计划哈希；API Key 只出现**环境变量名**，界面任何位置都不存、不显示密钥值。
4. **现代美观**。深/浅/跟随系统三态主题、统一的颜色/字体/间距 token、圆角卡片、克制的阴影与动效、一致的空状态。
5. **渐进式交付**。尚未实现的功能以 `TODO` 徽标呈现，入口可点但进入"即将推出"占位页，页内列出目标阶段。

## 2. 信息架构（导航分类）

采用经典"侧边栏 + 顶栏 + 内容区 + 状态栏"框架。一级导航按工作流分组：

```text
CircuitFabric
│
├─ 总览            Overview        仪表盘：项目/文档/bridge/任务/待审批 健康总览
│
├─ 项目            Projects        项目 CRUD + 项目级配置入口
├─ 文档            Documents       授权硬件文档登记 / 检索 / 证据包
├─ 电路语义        Semantics       快照谱系 / 拓扑 / 约束 / 语义查询
│
├─ EDA 服务        EDA Services    backend/bridge 插件健康与连接
├─ 智能体与工具    Agents & Tools  运行时端点 / LLM Provider / 技能与 MCP 授权
├─ 会话与任务      Sessions        会话回放 / 任务进度 / 事件轨迹
│
├─ 变更与审批      Changes         ChangeSet / IR Diff / 验证报告 / 回滚
├─ BOM 与导出      BOM & Export    BOM 导出 / 网表 / SPICE
│
├─ 插件            Plugins         manifest / 版本锁 / 签名 / 权限 / 健康
├─ 用量与审计      Usage & Audit   Token 用量 / 审计日志
│
└─ 设置            Settings        主题 / 语言 / 数据目录 / 密钥存储 / 关于
```

分组语义：

- **设计与证据**（总览、项目、文档、电路语义）：围绕"一个项目的设计事实从哪来、现在是什么"。
- **运行与工具**（EDA 服务、智能体与工具、会话与任务）：围绕"谁在改、通过什么工具、会话进展如何"。
- **物化与交付**（变更与审批、BOM 与导出）：围绕"改动如何被审、如何落到 EDA、如何导出"。
- **治理**（插件、用量与审计、设置）：围绕"插件可信吗、花了多少、全局怎么配"。

## 3. 全局框架（Shell）

### 3.1 顶栏（Top bar）

```text
┌─ [☰] ─ [项目选择器 ▾] ───────────────── [全局搜索 / 命令面板 ⌘K] ── [●运行] [Provider] [🌙] [🔔] [⚙] ─┐
```

- **左**：侧边栏折叠按钮；项目选择器（下拉，显示项目名 + 状态点，切换后内容区跟随项目上下文）。
- **中**：全局搜索框，聚焦即触发命令面板（`Ctrl+K`），可搜项目 / 文档 / 会话 / 命令。
- **右**：运行时状态指示（Codex App Server / bridge 在线为绿、离线为灰）、默认 Provider 徽标、主题切换、通知、设置。

### 3.2 侧边栏（Sidebar）

- 分组标题 + 线性图标 + 文本；折叠后仅图标。
- 未实现模块在图标旁显示 `TODO` 小徽标（灰色圆点）。
- 底部固定：设置、帮助、版本。

### 3.3 状态栏（Status bar）

- 左：bridge 地址与健康、默认 Provider、最近一次验证状态（复用第 4.2 节的状态色）。
- 右：版本号、数据目录路径、打开日志。

### 3.4 内容区

模块内容区统一为三态之一：**列表 + 详情**（项目、文档、会话、变更、插件）、**表单**（智能体与工具、设置）、**仪表盘**（总览、用量）。

### 3.5 审批抽屉（Approval drawer）

高危物化审批不弹模态框，而是从右侧滑出抽屉，内容见 5.8。

## 4. 视觉设计系统（Design tokens）

### 4.1 主题

浅色 / 深色 / 跟随系统，三态可切。全部颜色走语义 token，不散落硬编码色值。

### 4.2 状态色（核心语义）

把契约里的 `FactStatus` 直接映射为全站状态色，保证"写入/回读/验证"的语义始终一致：

| `FactStatus` | 颜色 | 含义 |
| --- | --- | --- |
| `passed` | 绿 | 通过 |
| `failed` | 红 | 失败 |
| `inconclusive` | 琥珀 | 未知 / 未能回读（**绝不显示为成功**） |
| `not_run` | 灰 | 未运行 |

另有中性色板：`surface`（页面底）、`surface-muted`（卡片底）、`canvas`（图表底）、`text` / `text-muted` / `text-faint`、`border` / `border-strong`，以及品牌主色 `accent`（沿用 logo 的电路绿/蓝）。

### 4.3 字体与排版

- 层次：`display` / `title` / `heading` / `body` / `caption` / `mono`。
- `mono`（等宽）用于一切机器标识：snapshot hash、provider id、内容哈希、引用定位符、命令。

### 4.4 间距与圆角

- 间距走 4px 栅格（`4/8/12/16/24/32`）。
- 圆角：`sm 6` / `md 8` / `lg 12` / `xl 16`。

### 4.5 图标

统一线性图标风格，每个一级模块配一个标识图标（总览=网格、项目=文件夹、文档=文档页、语义=拓扑节点、EDA 服务=插头、智能体=机器人、会话=对话气泡、变更=分支、BOM=清单、插件=拼图、用量=柱状图、设置=齿轮）。

### 4.6 基础组件

`Button`（primary / secondary / ghost / danger）、`Card`、`List`、`Table`、`Tabs`、`SegmentedControl`、`Badge`/`Tag`（状态徽标、`TODO` 徽标）、`Modal`、`Drawer`、`Toast`、`EmptyState`、`CommandPalette`、`StatusDot`。

## 5. 各页面设计

### 5.1 总览（Overview）

仪表盘。顶部四个 KPI 卡片：项目数、已授权文档数、在线 bridge 数、待审批变更数。下方三栏：

- **运行时健康**：Codex App Server、JLC bridge 的连接卡片（状态点 + 地址 + 最后心跳）。
- **最近会话/任务**：时间线（最近 5 条，含项目、运行时、状态）。
- **待办**：待审批 ChangeSet、未决身份冲突、`inconclusive` 验证结果。

```text
┌ 项目数 3 ┐ ┌ 文档 12 ┐ ┌ 在线 bridge 1 ┐ ┌ 待审批 2 ┐
┌─ 运行时健康 ────────────┐ ┌─ 最近会话/任务 ──────┐ ┌─ 待办 ──────────┐
│ ● Codex App Server 在线 │ │ ● s_01 项目A 已完成  │ │ ! ChangeSet #12  │
│ ● JLC bridge  127.0.0.1 │ │ ○ s_02 项目A 进行中  │ │ ! 身份冲突 x2     │
│ ○ 无 bridge-ui 会话     │ │ ...                 │ │ △ 回读 inconclu.. │
└────────────────────────┘ └──────────────────────┘ └──────────────────┘
```

已实现：本页是与「智能体与工具」同构的**多 EDA 服务管理**双栏界面——左栏按 EDA 后端逐卡片管理（当前只有 JLCircuit，后续后端作为新条目接入），右栏展示所选服务的详情。JLCircuit 卡片管理完整的 bridge 服务：**监听地址**（仅限回环地址，写入运行时设置，bridge 下次启动时生效）；**受监管的子进程**在本页启动与停止（状态芯片：启动中 / 运行中 · PID / 已停止 / 启动失败，进程自行退出时带回它的 stderr）；分层**状态监测**：页面打开期间每 5 秒一次的自动 TCP 探测区分 离线 / 在线 / 尚未探测，且不会干扰 bridge 的唯一 WebSocket 客户端；显式**连接测试**执行协议级 `status` 往返，回报协议版本、bridge 自报的能力（仅在成功回报后显示，从不在未上报时展示为可执行）以及已注册项目 ID——项目列表为空时给出警示，因为 EDA 插件的 `hello` 会因无已注册项目而被拒绝；端口可达但进程不是本应用启动时会标注为外部运行。

## 6. 关键交互流程

1. **高危物化审批流**：变更与审批 → 打开抽屉 → 展示基线快照 + 计划哈希 → 批准/拒绝；基线失配禁用批准并提示，落审计。
2. **空状态**：每个模块首次访问给出引导动作（如文档页空状态引导"登记第一个授权文档"）。
3. **TODO 占位**：未实现入口可点，进入"即将推出"占位页，列出目标阶段与验收标准（引用 `implementation-plan`）。
4. **状态一致性**：写入成功 / 回读成功 / 验证成功三者独立显示，`inconclusive` 恒为琥珀。
