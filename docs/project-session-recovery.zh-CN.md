项目会话按用途保存到项目根目录，重启应用或 EDA bridge 后仍可读取。

| 入口 | 分类目录 | 可见会话 |
| --- | --- | --- |
| EDA 面板、项目详情「会话」页 | `sessions/eda/` | 当前项目的 EDA 会话 |
| 文档预览「数据」页 | `sessions/datasheet/` | 当前项目、当前文档的提取会话 |
| 项目智能体／运行时任务入口 | `sessions/runtime/` | 当前项目的运行时任务 |

每个会话有 Markdown 审计记录。Codex 的完整运行时历史和应用保存的 thread 绑定在对应分类的 `<session-id>/codex/` 下。应用保存用途、项目和文档归属；Codex App Server 保存自己的对话历史，并提供 `thread/resume`。两者配合使用，不能用审计摘录替代运行时历史。

侧栏「会话与任务」提供分类切换，每次仅显示选中的一类。总览中的「查看会话」自动选择原记录的类别。旧版记录可在「旧版审计」查看。

桌面端各会话入口复用同样的列表行，显示时间、状态、运行时、会话标识和 Token 用量。文档「数据」页仍只列出当前文档的提取会话；历史较多时列表独立滚动。

点击记录会打开窗口级「会话详情」弹窗，正文按 Markdown 渲染标题、强调、列表、引用、代码块和表格，支持文字选择和复制。长记录在正文区滚动，标题与关闭按钮固定可见；弹窗随窗口大小收缩。点击「关闭」、遮罩或按 Esc 返回原页面，文档及滚动位置保留。运行时入口关闭弹窗后保留选中记录，可以继续该会话。

新保存的多行消息保留换行和 Markdown 结构。旧版记录会按已有内容解析，早期已合并掉的换行不能自动还原。

会话弹窗在打开时生成独立的展示副本，将审计事件标题和消息拆成 Markdown 顶层块，解除整篇审计列表的嵌套。阅读时复用已解析内容及块高度，按视口渲染，避免拖动滚动条时反复布局整段对话。原始审计文件、事件定位和运行时历史不变，仍支持完整记录的选择与复制。

旧版被合并成单行的长提示词会在展示副本中增加段落间隔，使单个文本块的布局量保持有限；原字符全部保留。已有强调、代码块、表格和嵌套列表不拆分，以保留格式。只在打开记录时生成并解析这份副本，拖动时不重新加载文件或解析 Markdown。

恢复操作：

- EDA：选择项目后，在 EDA 会话列表中选中原会话，查看记录并继续发送消息。「清空」创建新会话，不删除已有历史。
- 结构化提取：重新打开项目和原文档，切换到「数据」页，点击「继续」。完成的类别输出、已验证 Jev 批次、未完成批次中的成功判断和恢复反馈会从磁盘断点加载。每个文档拥有独立断点，其他文档的提取不会覆盖它。
- Codex 运行时任务：在该入口的会话历史中选中记录，输入下一条消息，点击「继续选中的会话」。普通「执行任务」创建新记录。Claude/DSH 保留分类审计记录，当前未实现它们的原生会话恢复。

提取断点在 `sessions/datasheet/checkpoints/` 中，每次类别或判断批次推进后原子写入；完成提取并保存最终结果后移除该文档断点，历史会话保留。恢复先校验项目、文档身份和内容哈希；损坏或过期的断点明确报错。判断后端变化时重新复核相关缓存。Codex Provider、模型或工具配置/授权发生变化时，原会话的继续请求会明确拒绝，用户可新建会话；旧历史保留。

恢复使用当前凭据，不把 API 密钥值写入应用的 thread 绑定或提取断点。额度恢复后仍需要点击继续；加载历史本身不触发模型请求。恢复对话会开始一个后续轮次，不会续接已失败请求的一半输出。未完成的在途步骤可能重新执行；已完成并落盘的步骤会复用。

旧版本 `sessions/*.md` 没有可靠的类别和 thread 绑定，保留为 `legacy`，仍参与审计统计，不混入新分类入口，也不能据此重建已经被清理的原 thread。

协议：EDA bridge 新增只读 `list_sessions` 与 `load_session` 消息，始终限定已选择项目和 `eda` 分类；聊天使用同一会话的持久 thread，不再依赖连接内存中的拼接历史。

验证覆盖：项目重开与类别/文档筛选、运行时进程退出后恢复同一 thread、额度失败后的续跑、累计 Token 去重、损坏断点和文档哈希变化、EDA WebSocket 历史接口与跨类别拒绝，以及原生 GPUI 中四类记录逐类显示和原类别回放。运行时恢复测试使用模拟 App Server，不调用付费模型。真实 EDA 安装及真实模型的重启续跑仍需人工验收。
